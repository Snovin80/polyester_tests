client.addressBook
manages saved transfer destinations, tags, whitelist views, and recent
counterparties. Every method is authenticated and account-scoped: inputs accept an optional
account
field (
"main"
,
"active"
, or
) that selects the root or
subaccount
book. See
Account scoping
for how the default
resolves. Creates, updates, and deletes need the
manage-address-book
policy action. A key without that action gets
AuthenticationError
on
writes. Reads still work.
Destinations come in two kinds:
external
(an on-chain address on a specific chain) and
internal
(another Polyester account by smart-account address). These feed the
internal transfer
and
withdrawal
flows.

	| { scopeType: "unspecified"; rootAccountId: string; subaccountId?: string };
