### F2. POST /v1/orders/preview: справочник обещает quote debit и fees, их нет

В доках: api-docs `rest__POST__v1__orders__preview.txt` — «Check current order eligibility and available balance, and preview resolved quantity, price protection, quote debit, and fees.»; поля ответа: admissible, evaluatedAt, protectedPriceBound, rejection, resolvedBaseQty (полей fee/debit нет). developer-docs `shared-concepts__preview-order.txt` — «Preview does not return expected fills, order-book depth, quote debit, fees, net proceeds, or required balance.»
На деле (вызов безопасный — preview ничего не ставит): `POST /v1/orders/preview` {"order":{…"symbol":"ETH-USDT","side":"BUY","baseQty":"0.005","marketIoc":{}…}} — 17:32:56.394 UTC, HTTP 200: `{"admissible":true,"evaluatedAt":"2026-09-29T17:32:56.565387162Z","protectedPriceBound":"2733.66","resolvedBaseQty":"0.005"}`. Комиссии и quote debit нет — прав developer-docs, описание в справочнике неверно.
Дополнение к «scaled»: protectedPriceBound — «Protective execution boundary in quote units scaled by 1e9», на деле десятичная строка «2733.66».
Пример тела из справочника (с subaccountId) — 403 API_KEY_ROOT_SCOPE_ONLY (ключ корневой, не баг); без subaccountId — 200 `{"admissible":false,…,"rejection":{"code":"STALE_QUOTE"}}` (clientRefPrice 0.005 для BTC-USDT — пример непригоден, мелочь).

## Мелочи «by design» (в отчёт не включать)

Из прогона на 3.12: в /v1/chain/* коды ошибок строчными (invalid_request, invalid_argument), в остальном API — заглавными; /v1/auth/transfer-destinations на неверный limit отвечает text/plain «bad request» / «bad limit»; «только сессия» в auth отвечают в формате Connect {"code":"permission_denied","message":…}, а не problem+json; в flows, subaccounts, address-books пропущены нулевые поля. Поля trading/rate-limits, vip/tiers, rate-limits, deposit-withdraw/config, deposit-addresses совпали с примерами.

spot/config `listingAt` объектом {seconds,nanos} вместо строки; лишний параметр (foo=1) везде молча игнорируется; transfers `source/destination.chainId` нет при нуле; коды ошибок limit разные (INVALID_LIMIT / INVALID_ARGUMENT / BAD_REQUEST); limit=0 где-то «по умолчанию», где-то 400.

## Не проверено

Страницы /v1/auth/subaccounts/{id}… — «только сессия» (с десятичными id в примерах), не вызывались. Эндпоинты из F3 сверены через Python 3.12 на компьютере автора (29.09 18:40 UTC, `docs/raw_sweep_local312.jsonl`) — итоги в F4–F7 и в «Мелочах».
